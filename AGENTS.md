# LeafDank — обязательные правила разработки

Эти правила применяются к любому разработчику и AI-агенту (включая Codex).

## Миссия
LeafDank — Android-форк DankChat с расширенными опциональными функциями по образцу Leafyrino. **Минимализм DankChat по умолчанию, максимальная функциональность по запросу**. Любые улучшения должны сохранять работоспособность исходного клиента.

## Границы и разрешения
- Работать только в пределах LeafDank и явно выбранных пользователем файлов/задач.
- Чтение публичных upstream-репозиториев разрешено. Любое изменение удалённого GitHub (commit/push/branch/PR/issue/release/config) требует явного разрешения владельца непосредственно перед действием.
- Нельзя молча удалять функции, тесты, лицензионные уведомления, переводы, ресурсы, Gradle-конфигурации и данные пользователя.
- Нельзя массово рефакторить код, заменять стек, добавлять SDK, телеметрию и аналитику без обоснования и согласования.
- Не создавать «красивые» абстракции без реальной потребности. Сначала искать существующую реализацию в DankChat.

## Техническая основа
- Kotlin, Coroutines и Jetpack Compose — основной Android-стек. Rust/C++ допустимы только после профилирования и доказанной пользы; NDK/JNI не вводить по умолчанию.
- Leafyrino (C++/Qt) использовать как источник требований и проверенных идей; переносить лишь отдельные алгоритмы по итогам анализа лицензий и зависимостей.
- Один сетевой слой, одна база/хранилище и единое состояние чата; Classic/Modern/Custom — только альтернативные представления UI.
- Не переписывать приложение с нуля и не дублировать его ради двух интерфейсов.

## Авторизация и безопасность
- Использовать документированные потоки OAuth с собственным зарегистрированным Twitch Client ID; запрашивать минимальные scopes, явно показывать разрешения и обеспечивать отзыв.
- Legacy Login, вставка браузерных токенов, скрипты для извлечения cookies и выполнение удалённого JavaScript — вне плана.
- Не копировать внутренние Twitch TV/Web Client ID и токены из других проектов для выдачи себя за официальный клиент.
- Никаких client secrets в APK, репозитории или логах. Защищать токены с помощью Android Keystore и связанного защищённого хранилища; токены не должны экспортироваться вместе с настройками.
- Channel Points/награды/прогнозы через внутренний GraphQL Twitch — НЕ гарантированная функция. Не выпускать без отдельной проверки доступности, безопасности и правил Twitch. При недоступности интеграций чат продолжает работать.

## Пользовательский интерфейс
- Интерфейс по умолчанию остаётся лёгким и знакомым пользователям DankChat.
- Все дополнительные функции можно отключить. Пользователь отдельно выбирает Classic, Modern или Custom и компоненты (сообщения, вкладки, шапка, поле ввода, карточки, смайлики).
- Переключение UI не должно переподключать Twitch, удалять историю, черновики или состояние вкладок.
- Глобальные настройки и необязательные настройки канала; версии настроек и миграции; экспорт без секретов.
- Проверять доступность: TalkBack, масштаб текста, контраст, удобные сенсорные зоны.

## Производительность
- Цель — измеримо эффективный чат, а не произвольные заявления о превосходстве Rust.
- Lazy-список сообщений, ограниченные по памяти/диску кэши GIF/эмоутов, отмена загрузок, пауза невидимых анимаций, экономия батареи.
- Измерять PSS/RSS, плавность скролла, время открытия и батарею на конкретных устройствах, с базовой сборкой DankChat в качестве контроля. Целевые бюджеты установить после измерений.
- Не оптимизировать без профиля и не удалять baseline profile/benchmark ради очистки репозитория.

## Процесс изменения
1. Зафиксировать актуальный upstream commit, проверить git status, зависимости и затрагиваемые файлы.
2. Описать пользовательский сценарий, риски, способ отката и критерии приёмки.
3. Делать малые, логически законченные изменения; избегать не относящихся к задаче рефакторингов.
4. Добавлять тесты/регрессии. Проверять formatter, detekt, Android Lint, unit tests и build по возможностям среды; не заявлять о пройденных проверках без вывода.
5. Перед передачей перечислить изменённые файлы, фактические проверки, оставшиеся риски и состояние git.
6. Комментарии в коде — на русском, только если решение неочевидно. Код и документация без сарказма и декоративного мусора.

## Лицензии и релиз
- Сохранить LICENSE DankChat и уведомления об авторских правах на заимствованный код; происхождение перенесённых фрагментов Leafyrino отмечать точным commit/path.
- Для отдельной установки понадобится собственный applicationId (план: dev.akseleron.leafdank), независимый signing key и корректная OAuth-регистрация. Не распространять APK оригинала под именем LeafDank.
- Приоритет: стабильная работа чата > безопасность > производительность > дополнительные функции > визуальная отделка.

## Референсные исходники Leafyrino
- Проверенный C++/Qt-референс хранится в Git-субмодуле `references/leafyrino`, закреплённом на коммите `de8cd64fe2f011448c70ac2b46cd88193bc47089`.
- Если исходники не появились после клонирования, для чтения достаточно `git submodule update --init references/leafyrino`; **не нужно** скачивать вложенные C++ зависимости через `--recursive`.
- Не менять содержимое `references/leafyrino` и зафиксированную ревизию без отдельного разрешения владельца; не добавлять референс в сборку Android.
- Перед реализацией изучать исходники и фиксировать путь/коммит. Сводная карта: `docs/SOURCE_REFERENCES.md`.
